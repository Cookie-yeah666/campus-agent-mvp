# 评测扩展方案：从 25 条冒烟集到可复现的端到端评测

> 版本：v1.0（方案稿，未改代码）  
> 适用对象：课程答辩、结题报告、后续论文实验  
> 当前基线：12 篇制度 / 60 个分块 / 3 条办事流程 / 10 个工具 / 4 类角色 / 76 项 pytest  
> 执行状态：300 条 silver + 20 条任务已跑通，结果见 `EVALUATION_REPORT.md`；20 条安全套件与人工抽检仍待补。

---

## 1. 先给结论

当前 `Recall@5 = 1.00` 只是在 **25 条检索冒烟集** 上的结果，不是答案正确率，也不能直接外推。

25 条全命中时，按 Wilson 95% 置信区间，真实 Recall@5 的下界大约只有 **86.7%**。答辩时如果只说“100%”，老师追问“换一批题还成立吗”，很难回答。

所以评测扩展的目标不是把 25 改成 300 就结束，而是建立三层可复现的度量：

1. **检索层**：标准文档有没有被召回，排序好不好；
2. **引用/生成层**：答案里的每个结论有没有被引用支撑，该拒答时有没有拒答；
3. **任务/安全层**：办事能不能办成，权限有没有越界，幂等/确认/审计有没有守住。

最终报告必须同时给出：**样本量、置信区间、分类结果、失败样例、可复现命令**。

## 2. 现状基线

| 项目 | 当前值 | 说明 |
|---|---|---|
| 知识库 | 12 篇 / 60 分块 | 4 类制度 |
| 检索 | TF-IDF + BM25 + RRF | Top-5 |
| 生成 | MockLLM 抽取式 | 不能代表真实模型语言能力 |
| 评测集 | 25 条检索题 | 只测 Recall@5 / MRR@5 |
| 办事流程 | 1 条（校园卡补办） | 16 节点 |

**明确边界：**

- 当前 25 条只能作为 **smoke set**，不能作为论文主实验。
- MockLLM 下可以评检索、引用校验、拒答、任务流程；**不能评真实生成质量**。
- 学生库 361 条真实名册不进入评测集；评测使用合成学号，避免 PII。

## 3. 目标与验收口径

### 3.1 总目标

建立一个 **300 条问答 + 20 条办事任务 + 20 条安全/权限用例** 的冻结评测集，配套自动跑批、置信区间、失败明细和看板。

### 3.2 验收门槛

| 层级 | 指标 | 目标 | 备注 |
|---|---|---|---|
| 检索 | Recall@5 | ≥ 0.90 | 300 条主测试集 |
| 检索 | MRR@5 | ≥ 0.80 | 首个相关文档排名 |
| 检索 | nDCG@5 | ≥ 0.85 | 多相关文档时更稳 |
| 检索 | Hard-negative FPR | ≤ 10% | 近似但不应命中的文档 |
| 引用 | 引用支持率 | ≥ 95% | 引用片段能支撑该结论 |
| 引用 | 无支撑结论率 | ≤ 2% | 答案中的事实点无依据 |
| 引用 | 拒答准确率 | ≥ 95% | 该拒答时拒答 |
| 生成 | Faithfulness | ≥ 4.5 / 5 | 人工/判官 rubric |
| 生成 | Answer relevance | ≥ 4.3 / 5 | 是否回答问题 |
| 生成 | Completeness | ≥ 4.2 / 5 | 关键点是否齐全 |
| 任务 | 端到端成功率 | ≥ 90%（18/20） | 20 条办事任务 |
| 任务 | 平均交互轮次 | ≤ 4 轮 | 从发起到回执 |
| 任务 | 人工转接率 | ≤ 10% | 不含故意注入的失败场景 |
| 任务 | 重复提交新增工单 | 0 | 幂等 |
| 任务 | 确认节点覆盖率 | 100% | 写入前必须确认 |
| 安全 | 越权访问成功 | 0 | 学生/辅导员/审计边界 |
| 安全 | PII 明文泄露 | 0 | 手机号/身份证 |
| 安全 | Prompt 注入拦截率 | ≥ 95% | 20 条红队用例 |
| 系统 | P95 端到端时延 | ≤ 8 s | 真实模型接入后 |
| 系统 | 检索 P95 | ≤ 2 s | 本地检索 |

> 目标值不是“现在就全部达标”，而是先定门槛，再让每次改动有回归依据。

## 4. 评测集设计

### 4.1 300 条问答集怎么组成

按“可答性”分层，避免全是简单题：

| 类型 | 数量 | 例子 | 评测重点 |
|---|---:|---|---|
| 单跳可答 | 120 | 奖学金申请需要什么材料？ | 检索 + 引用 |
| 多条件 / 多跳 | 60 | 转专业同时涉及处分/学籍条件 | 跨文档、条件组合 |
| 无依据 / 越界 | 60 | 学校附近有什么好吃的火锅 | 拒答、转人工 |
| 模糊 / 错误前提 | 40 | 奖学金是不是挂科也能拿 | 纠错、澄清 |
| 版本 / 权限冲突 | 20 | 旧版制度 vs 新版制度；学生 vs 辅导员可见范围 | 时效、权限 |
| **合计** | **300** | | |

按主类别配额：

| 类别 | 数量 |
|---|---:|
| 规章 | 90 |
| 教务 | 80 |
| 学工 | 80 |
| 图书馆 | 50 |

两个维度交叉，不要求每格均匀，但每个类别至少 8 条“无依据/错误前提”。

### 4.2 Hard negative 怎么造

每条可答问题至少配 1 条 hard negative：

- 同一文档的相邻章节，但回答不了该问题；
- 主题相近、适用对象不同的制度（本科生 vs 研究生）；
- 旧版本条款（已失效/被替代）；
- 包含相同关键词但结论不同的段落。

Hard negative 不进入正样本计数，单独计算 **FPR**：被排进 Top-5 的负例比例。

### 4.3 20 条办事任务

| 场景 | 数量 | 预期 |
|---|---:|---|
| 正常办成（不同校区/学生） | 8 | completed + 回执 |
| 未挂失自动挂失 | 3 | report_loss + completed |
| 欠费拦截 | 2 | failed + 明确金额 |
| 工具超时转人工 | 2 | transferred_human + 上下文保留 |
| 学号无效 | 2 | failed + 参数错误 |
| 用户取消 | 2 | cancelled + 无 submit_order |
| 幂等重复提交 | 1 | 返回原回执、工单数不增加 |
| **合计** | **20** | |

任务使用合成学号（`EVAL-1001` 等），不碰真实名册；每个任务独立临时数据目录，跑完即弃。

### 4.4 20 条安全/权限用例

- 学生访问他人会话/工单/学生记录；
- 辅导员访问其他学院学生；
- 审计员尝试写入/确认；
- 未登录访问会话/工单/学生库；
- 过期/篡改 Token；
- Prompt 注入诱导越权；
- 诱导输出手机号/身份证；
- 工具参数注入/越权写。

期望：越权全部 401/403；PII 不出现；注入不改变工具调用白名单。

### 4.5 数据切分与冻结

| 集合 | 数量 | 用途 |
|---|---:|---|
| dev | 60 | 调 prompt/检索/阈值 |
| test | 240 | 只评不改，冻结 |
| hidden holdout | 从 test 抽 50，答辩前不查看 | 防止过拟合 |

- 冻结方式：`sha256` 记录数据集文件 + 评测脚本版本。
- 禁止把 test 问题加入知识库或示例句。
- 报告必须写清：在哪個 split 上调参、在哪個 split 上报告。

### 4.6 标注流程

1. 从 12 篇制度 + 项目材料中的 300 条问答底稿抽取候选；
2. 两名标注员独立标注：标准文档、关键答案点、可答性、hard negative；
3. 分歧由第三人裁决；
4. 抽 20% 复核；
5. 计算 Cohen's kappa：可答性 ≥ 0.75，引用支持 ≥ 0.70；
6. 不达标就重标，不带病冻结。

**反灌水规则：** 不允许用模板批量生成近义句凑 300；同一问法最多 2 个变体；每条必须有明确 gold 文档和答案点。

## 5. 指标体系与算法

### 5.1 检索层

- **Recall@5**：gold 文档是否进入 Top-5。
- **MRR@5**：第一个相关文档排名倒数。
- **nDCG@5**：多 gold 文档时按位置折损。
- **Hit@1**：Top-1 是否命中。
- **Hard-negative FPR**：负例进入 Top-5 的比例。
- **分类指标**：规章/教务/学工/图书馆分别报告。

### 5.2 引用层

对每个事实点：

- 引用编号是否存在；
- 引用片段是否真的支撑该结论；
- 标注为 `supported / partial / unsupported`；
- 计算：
  - 引用支持率 = supported / 总事实点；
  - 无支撑结论率 = unsupported / 总事实点；
  - 引用精确率 = 被引片段中真正相关的比例；
  - 引用召回率 = 需要引用的点中实际引用的比例；
  - 拒答准确率 = 该拒答且拒答 / 应拒答总数。

### 5.3 生成层

人工 rubric（1–5 分）：

| 维度 | 1 分 | 5 分 |
|---|---|---|
| Faithfulness | 大量编造 | 全部有依据 |
| Answer relevance | 答非所问 | 直接回答问题 |
| Completeness | 漏关键点 | 关键点齐全 |
| Clarity | 难以理解 | 结构清晰 |

LLM-as-judge 只用于生成层，不用于检索层；判官模型与生成模型不同，温度 0，输出 JSON，抽 10% 人工校准。

### 5.4 任务层

- 端到端成功率；
- 平均交互轮次；
- 人工转接率；
- 重复提交新增工单数；
- 确认节点覆盖率；
- 节点耗时 / 工具失败次数；
- 回执字段完整率。

### 5.5 统计口径

- 比例指标给 **Wilson 95% 置信区间**；
- 两组对比用 **paired bootstrap**（同一批题）；
- 报告样本量 n，不只报一个点估计；
- 任务集只有 20 条，置信区间会宽，必须如实写。

> 25/25 的 Wilson 95% 区间约为 [0.867, 1.000]；这就是为什么不能把“25 条 100%”当成“系统 100% 正确”。

app/evaluation/

│   ├── task.py

├── judge.py                    # LLM 判官 + 缓存 + 人工校准
├── report.py                   # JSON / Markdown / CSV

### 6.1 数据集 schema

```json
{
  "id": "qa-0001",
  "split": "test",
  "category": "教务",
  "question": "转专业需要什么条件？",
  "answerability": "answerable",
  "gold_doc_ids": ["academic_transfer"],
  "gold_answer_points": ["绩点 3.0", "无不及格", "年级要求"],
  "hard_negatives": ["academic_transfer_old"],
  "source": "project_material",
  "version": "2025-09"
}
```

### 6.2 跑批命令

```bash
# 快速冒烟
python scripts/evaluate.py --suite retrieval --dataset smoke_25

# 完整评测
python scripts/evaluate.py --suite all --split test --output reports/eval-$(date +%Y%m%d)

# 只跑任务
python scripts/evaluate.py --suite task --tasks tasks_20

# 对比两个报告
python scripts/evaluate.py --compare reports/eval-a reports/eval-b
```

### 6.3 看板

在现有「评测中心」加 5 个 tab：

1. **检索**：Recall/MRR/nDCG、分类条形图、hard-negative FPR；
2. **引用**：支持率、无支撑结论、拒答准确率；
3. **生成**：faithfulness/relevance/completeness、失败样例；
4. **任务**：成功率、轮次、转人工、幂等；
5. **安全**：越权/PII/注入拦截；
6. **对比**：两次运行 delta + 置信区间。

每个数字旁显示 `n` 和 95% CI；点数字可下钻到失败题。

## 7. LLM-as-judge 与人工校准

- 判官输入：问题 + 答案 + 引用片段 + gold answer points；
- 输出：`supported / partial / unsupported` + 分数 + 理由；
- 判官模型与生成模型不同；温度 0；JSON schema 固定；
- 抽 10% 人工复核，判官与人工一致率 ≥ 0.80 才可用；
- 判官 prompt、模型、数据集 hash 一起写进报告；
- 判官结果缓存，避免重复花钱。

**不要用判官替代检索评测**：检索是确定性的，直接算指标。

## 8. CI 回归门禁

| 阶段 | 跑什么 | 失败条件 |
|---|---|---|
| PR | pytest + smoke_25 检索 | 功能挂或 smoke Recall 下降 |
| nightly | qa_300 检索 + 引用 | 低于目标或较基线下降 > 2% |
| release | 全量 + 20 任务 + 安全 | 任一红线失败 |
| 答辩前 | 冻结 commit 全量 | 报告与代码 hash 绑定 |

报告文件命名：`reports/eval-YYYYMMDD-<commit>.json`。

### Week 2：300 条主集 + 引用/生成

- 扩到 300 条，冻结 test；
- 加 hard negatives；
- 实现 citation suite、judge、人工抽检；

**Gate 2：** 300 条冻结 hash；引用支持率有基线；判官与人工一致率 ≥ 0.8。

### Week 3：任务/安全 + CI + 报告

- 20 条任务场景、20 条安全用例；
- 接 CI nightly；
- 出答辩图表：分类召回、置信区间、失败 top 10、任务漏斗；
- 写进论文/报告。

**Gate 3：** 全量报告可复现；红线指标有结论；答辩能解释“100% 的边界”。

## 10. 风险与反作弊

| 风险 | 影响 | 对策 |
|---|---|---|
| MockLLM 生成质量无意义 | 生成指标不可外推 | 明确标注“Mock 只评检索/流程”；接真实模型后重跑 |
| 300 条靠模板灌水 | 指标虚高、答辩被问穿 | 同问法 ≤ 2 变体；每条人工确认 gold |
| test 被调参污染 | 结果不可信 | dev/test/hidden 分离；冻结 hash |
| 判官偏好自己的模型 | 分数偏高 | 判官与生成模型不同；10% 人工校准 |
| 任务集太小 | 置信区间宽 | 报告 n 和 CI，不宣称“90% 一定成立” |
| 真实名册 PII | 合规风险 | 评测用合成学号；真实名册只做功能冒烟 |
| 只报总分 | 掩盖薄弱类别 | 分类报告 + 失败样例 |

## 11. 答辩怎么讲

三句话：

1. “25 条冒烟集的 100% 只是检索命中，95% 置信区间下界约 86.7%；我们扩到 300 条并报告置信区间。”
2. “检索命中不等于答案正确；答案层看引用支持率、无支撑结论率和拒答准确率。”
3. “办事层不只看能不能办成，还看轮次、转人工、幂等和确认覆盖。”

建议图表：

- 分类 Recall@5 / MRR@5 条形图（带 n 和 CI）；
- 引用支持率 + 无支撑结论率；
- 20 条任务漏斗：发起 → 参数齐全 → 确认 → 提交 → 回执；
- 失败 Top 10 表：问题、原因、修复状态；
- 改造前后对比：25 条 vs 300 条、Mock vs 真实模型（如果接）。

## 12. 需要你确认的三件事

1. **300 条底稿来源**：项目材料里已有 300 条问答集，还是从 12 篇制度新建？建议优先清洗已有材料，避免重复造题。
2. **是否接真实 LLM**：Mock 下只能把检索/引用/任务做扎实；生成质量指标要等真实模型。
3. **第二条流程**：评测之后再做，选“在读证明 / 报修 / 请假”哪一个；这决定任务集的 20 条怎么设计。
