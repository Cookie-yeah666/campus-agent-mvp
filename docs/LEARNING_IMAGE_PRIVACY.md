# 学习空间：题目图片本地化 vs 云端识别的选择

> 适用：AI 错题本、拍题识别、题图裁切、AI 批改  
> 结论先行：课程原型建议 **混合模式（裁剪/脱敏后上云）**；真实校园部署建议 **校内私有化或专属云**。

---

## 1. 一张照片里可能有什么

学生拍一张作业纸，图片里不只有题目，可能还有：

- 姓名、学号、班级；
- 人脸、宿舍、校服、校园卡；
- 其他题的答案、红笔批改；
- 地理位置 EXIF；
- 整页作业，而不是一道题。

所以“图片出不出校园网”不是抽象问题，而是：**哪一部分图片、以什么形式、发给谁、存多久、能否删除**。

---

## 2. 三种可选架构

### 方案 A：公有云多模态 API（图片出校网）

```text
学生手机/浏览器 → 学校服务器 → 公有云视觉模型 → 返回识别/批改
```

**做法：** 直接调用 Qwen-VL、豆包 Vision、GLM-4V、GPT-4o、Gemini 等。

**优点：**

- 识别和推理效果最好，尤其是手写、公式、复杂题图；
- 开发最快，不需要 GPU；
- 按量付费，演示阶段成本低；
- 模型持续升级。

**缺点：**

- 图片离开校园网，涉及个人信息/教育数据合规；
- 公有云可能保留日志、用于训练（取决于合同）；
- 境外模型涉及数据出境；
- 断网/限流时不可用；
- 长期调用成本随用量增长。

**适合：** 课程演示、无真实学生隐私的样例图、已签数据处理协议的公有云。

---

### 方案 B：混合模式（本地预处理 + 裁剪/脱敏后上云）

```text
原图 → 校内服务器：旋转/缩放/去 EXIF/检测题目区域/裁切
     → 只把“题目区域”或 OCR 文本发给云端
     → 云端识别/解析/批改
```

**做法：**

- 本地用 Pillow/OpenCV 做预处理；
- 本地 OCR（PaddleOCR/Pix2Text）先提取文字；
- 只上传裁剪后的题干/题图，或只上传文本；
- 姓名、学号、人脸、其他题不进入云端；
- 云端只负责它擅长的公式/图形理解和推理。

**优点：**

- 隐私明显好于整页上传；
- 识别效果仍接近云端模型；
- 开发量适中；
- 可以对不同学校切换“只传文本/传题图/整页”策略。

**缺点：**

- 仍然有图片/文本出校网；
- 本地裁切可能切错，复杂题图会丢上下文；
- 多一层 OCR，公式识别可能损失；
- 需要维护本地 OCR 依赖和图片处理逻辑。

**适合：** 课程原型、试点学院、允许“最小必要数据”出校网的学校。

---

### 方案 C：校内私有化（图片不出校网）

```text
学生 → 校内服务器 → 校内 GPU 上的视觉模型/OCR → 返回
```

**做法：**

- 校内 GPU 部署 Qwen2.5-VL-7B/72B、InternVL、MiniCPM-V 等；
- 本地 PaddleOCR/Pix2Text 做文字/公式；
- vLLM/Ollama 推理服务；
- 图片只在校内存储和流转。

**优点：**

- 隐私最好，图片不出校网；
- 可离线运行；
- 数据可控、可审计、可删除；
- 没有按次 API 费用。

**缺点：**

- 需要 GPU（7B 量化约 16–24GB 显存；72B 需多卡）；
- 部署、运维、模型升级成本高；
- 复杂手写/公式/题图效果通常不如顶级云端模型；
- 响应速度和并发受硬件限制；
- 课程原型阶段很难快速搭起来。

**适合：** 真实校园上线、明确要求数据不出校、有 GPU 和运维资源的学校。

---

### 方案 D：专属云/私有部署（合同约束，折中）

云厂商提供专属实例/VPC，数据不进入公共训练，签数据处理协议。  
效果接近公有云，合规比公有云好，但仍有云依赖和费用。适合学校已有云资源的情况。

---

## 3. 对比表

| 维度 | A 公有云 | B 混合 | C 校内私有化 |
|---|---|---|---|
| 识别效果 | 最好 | 较好 | 中等（取决于模型/GPU） |
| 隐私 | 最弱 | 中等 | 最好 |
| 开发速度 | 最快 | 中等 | 最慢 |
| 硬件成本 | 低 | 低 | 高 |
| 调用成本 | 按量 | 按量（更少） | 电费/运维 |
| 离线 | 不可 | 部分 | 可 |
| 合规风险 | 高 | 中 | 低 |
| 适合阶段 | 演示 | 试点 | 正式上线 |

---

## 4. 我的建议

### 课程原型/答辩阶段

选 **B 混合模式**：

- 原图只在校内服务器；
- 去 EXIF、裁题目区域；
- 只把题目区域或 OCR 文本发给云端；
- 页面上明确告知“图片会发送到模型服务用于识别”；
- 演示用样例图，不用真实学生作业。

### 真实校园上线

选 **C 校内私有化**，或 **D 专属云**：

- 数据不出校；
- 图片加密存储、7 天/30 天自动删除；
- 学生可撤回/删除；
- 管理员可审计访问；
- 模型服务单独隔离。

### 不建议

- 把整页作业原图直接发公有云；
- 把 API Key 放前端 localStorage；
- 把识别结果和原图无限期保存；
- 在演示时把 mock 识别说成真实识别。

---

## 5. 不管选哪个，都要做的隐私设计

1. **上传前告知**：图片用途、接收方、保存时长；
2. **最小必要**：只传题目区域，不传姓名/学号/人脸；
3. **去 EXIF**：移除定位和设备信息；
4. **加密存储**：图片和解析结果分开权限；
5. **保留期限**：默认 30 天，可配置；
6. **可删除**：学生删除错题本时删原图；
7. **访问控制**：学生只看自己的；管理员审计；
8. **密钥安全**：API Key 只存服务端，前端只显示掩码；
9. **供应商条款**：确认不用于训练、不留存、可签 DPA；
10. **降级策略**：模型不可用时，允许手动录入题目，不阻塞学习。

## 6. API Key 输入接口怎么做

当前实现是 **每个学生自己的 Key**：

```text
学生在「学习空间 → 模型设置」输入 Key
 → POST /learning/settings/vision
 → 服务端用 Windows DPAPI 加密
 → 写入 learning_data/learning.db
 → 返回掩码 sk-****1234
 → 前端永远拿不到完整 Key
```

- 每个学生只读写自己的配置；
- 未配置 Key 时拒绝识别，不返回 mock 题；
- Key 不写浏览器 localStorage；
- 保存后不可查看、不可覆盖，必须删除旧 Key 再录入；
- 数据库存 DPAPI 密文 + SHA-256 指纹，接口只返回掩码；
- 服务重启后仍可解密（DPAPI 绑定当前 Windows 用户）；
- 严格单向哈希不能用于调用模型；这是“接口不可读 + 加密存储”，不是“服务器永远无法解密”；
- 正式多用户服务器应改为 KMS/HSM 或专用密钥服务。

课程演示也可以用服务端 `.env` 统一配置，但当前业务路径优先使用学生自己的加密配置。

## 7. 需要你选的一个选项

- **A 公有云**：最快、效果最好，但图片出校网；
- **B 混合**：裁剪/脱敏后出校网，推荐课程原型；
- **C 校内私有化**：不出校网，但需要 GPU/运维；
- **D 专属云**：合同约束的折中方案。

你选定后，我再按“学习空间 + 专注计时 + AI 任务清单 + 日历 + 课程表 + 错题本”的顺序实施，避免视觉层返工。
